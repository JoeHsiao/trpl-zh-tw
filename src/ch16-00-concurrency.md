# 無畏併發

[ch16-00-concurrency.md](https://github.com/rust-lang/book/blob/9bd32402af8d3103302650895ec9d129ebfa47e1/src/ch16-00-concurrency.md)

安全且高效地處理併發程式設計，是 Rust 的另一個主要目標。**併發程式設計**（*concurrent programming*）指程式的不同部分彼此獨立地執行，而**並行程式設計**（*parallel programming*）則指程式的不同部分同時執行。隨著越來越多的計算機開始利用多處理器的優勢，這兩個概念正變得越來越重要。歷史上，在這些場景中程式設計一直都很困難且容易出錯。Rust 希望改變這一點。

起初，Rust 團隊認為確保記憶體安全和防止併發問題是兩個分別需要不同方法應對的挑戰。隨著時間的推移，團隊發現所有權和型別系統是一系列解決記憶體安全**和**併發問題的強有力的工具！通過利用所有權和型別檢查，在 Rust 中很多併發錯誤都是**編譯時**錯誤，而非執行時錯誤。因此，相比花費大量時間嘗試重現執行時併發 bug 出現的特定情況，不正確的程式碼會直接編譯失敗並提供解釋問題的錯誤資訊。因此，你可以在開發時修復程式碼，而不是在部署到生產環境後修復程式碼。我們給 Rust 的這一部分起了一個綽號**無畏併發**（_fearless concurrency_）。無畏併發令你的程式碼免於出現詭異的 bug 並可以輕鬆重構且無需擔心會引入新的 bug。

> 注意：出於簡潔的考慮，我們將很多問題歸類為**併發**，而不是更準確的區分**併發和/或並行**。對於本章，當我們談到**併發**時，請自行腦內替換為 **併發和/或並行**。在下一章中當區分二者更為重要時，我們會使用更準確的表述。

很多語言對它們所提供的併發問題解決方案都比較“教條”。例如，Erlang 擁有優雅的訊息傳遞併發功能，但線上程間共享狀態方面只有一些不那麼直觀的方式。對於高階語言來說，只支援可能解決方案中的一個子集，是合理的策略，因為高階語言通過放棄一部分控制權來換取抽象，並承諾由此帶來的收益。然而，底層語言通常被期望在任何給定場景下都能提供效能最佳的解決方案，並且對硬體施加更少抽象。因此，Rust 提供了多種工具，讓你能夠按照最適合自身場景和需求的方式來建模問題。

如下是本章將要涉及到的內容：

- 如何建立執行緒來同時執行多段程式碼。
- **訊息傳遞**（*message-passing*）併發，其中通道（channel）線上程之間傳送訊息。
- **共享狀態**（*shared-state*）併發，其中多個執行緒可以訪問同一份資料。
- `Sync` 和 `Send` trait，它們將 Rust 的併發保證擴充套件到使用者定義型別以及標準庫提供的型別。
