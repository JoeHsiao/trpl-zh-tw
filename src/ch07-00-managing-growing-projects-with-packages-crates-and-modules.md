# 包、Crates 與模組

[ch07-00-managing-growing-projects-with-packages-crates-and-modules.md](https://github.com/rust-lang/book/blob/79b9d15410a7b15a65cb86bcb40cbea99198a9e4/src/ch07-00-managing-growing-projects-with-packages-crates-and-modules.md)

當你編寫大型程式時，組織程式碼顯得尤為重要。通過對相關功能進行分組和劃分不同功能的程式碼，你可以清楚在哪裡可以找到實現了特定功能的程式碼，以及在哪裡可以改變一個功能的工作方式。

到目前為止，我們編寫的程式都在一個檔案的一個模組中。伴隨著專案的增長，你應該通過將程式碼分解為多個模組和多個檔案來組織程式碼。一個包（package）可以包含多個二進位制 crate 項和一個可選的庫 crate。伴隨著包的增長，你可以將包中的部分程式碼提取出來，做成獨立的 crate，這些 crate 則作為外部依賴項。本章將會涵蓋所有這些概念。對於一個由一系列相互關聯的包組成的超大型專案，Cargo 提供了**工作空間**（*workspaces*）這一功能，我們將在第十四章的 [“Cargo Workspaces”][workspaces] 對此進行講解。

我們也會討論封裝來實現細節，這可以讓你在更高層面重用程式碼：你實現了一個操作後，其他的程式碼可以通過該程式碼的公共介面來進行呼叫，而不需要知道它是如何實現的。你在編寫程式碼時可以定義哪些部分是其他程式碼可以使用的公共部分，以及哪些部分是你有權更改實現細節的私有部分。這是另一種減少你在腦海中記住專案內容數量的方法。

這裡有一個需要說明的概念 “作用域（scope）”：程式碼所在的巢狀上下文有一組定義為 “in scope” 的名稱。當閱讀、編寫和編譯程式碼時，程式設計師和編譯器需要知道特定位置的特定名稱是否引用了變數、函式、結構體、列舉、模組、常量或者其他有意義的項。你可以建立作用域，以及改變哪些名稱在作用域內還是作用域外。同一個作用域內不能擁有兩個相同名稱的項；可以使用一些工具來解決名稱衝突。

Rust 有許多功能可以讓你管理程式碼的組織，包括哪些細節可以被公開，哪些細節作為私有部分，以及程式中各個作用域中有哪些名稱。這些特性，有時被統稱為 “模組系統（the module system）”，包括：

- **包**（*Packages*）：Cargo 的一個功能，它允許你構建、測試和分享 crate。
- **Crates**：一個模組樹，可以產生一個庫或執行檔。
- **模組**（*Modules*）和 **use**：允許你控制作用域和路徑的私有性。
- **路徑**（*path*）：一個為例如結構體、函式或模組等項命名的方式。

本章將會涵蓋所有這些概念，討論它們如何互動，並說明如何使用它們來管理作用域。到最後，你會對模組系統有深入的瞭解，並且能夠像專業人士一樣使用作用域！
