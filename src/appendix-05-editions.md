## 附錄 E：版本

[appendix-05-editions.md](https://github.com/rust-lang/book/blob/555182e7f27ffb9761e18455f4d7eb42443a2954/src/appendix-05-editions.md)

早在第一章，我們見過 `cargo new` 在 *Cargo.toml* 中增加了一些有關 `edition` 的元資料。本附錄將解釋其意義！

Rust 語言和編譯器有一個為期六週的釋出迴圈，這意味著使用者會穩定得到新功能的更新。其他程式語言釋出大更新但不甚頻繁；Rust 選擇更為頻繁的釋出小更新。一段時間之後，所有這些小更新會日積月累。不過隨著小更新逐次的釋出，或許很難回過頭來感嘆：“哇，從 Rust 1.10 到 Rust 1.31，Rust 的變化真大！”

大約每三年左右，Rust 團隊會發佈一個新的 Rust **版本**（*edition*）。每一個版本會把已經落地的特性整合成一個清晰的整體，並配套提供完全更新過的文件和工具。新版本會作為常規六週釋出流程的一部分發布。

新的版本對不同人群具有不同意義：

- 對於活躍的 Rust 使用者，新版本將這些增量改進整合成一個易於理解的包。
- 對於非 Rust 使用者，它表明釋出了一些重大進展，這意味著 Rust 可能變得值得一試。
- 對於 Rust 自身開發者，它提供了專案整體的集合點。

在本文件編寫時，Rust 有四個可用版本：Rust 2015、Rust 2018、Rust 2021 和 Rust 2024。本書基於 Rust 2024 edition 慣用法編寫。

*Cargo.toml* 中的 `edition` 欄位表明程式碼應該使用哪個版本編譯。如果該欄位不存在，其預設為 `2015` 以提供後向相容性。

每個專案都可以選擇不同於預設的 2015 edition 的版本。這樣，版本可能會包含不相容的修改，比如新增關鍵字可能會與程式碼中的識別符號衝突並導致錯誤。不過除非選擇相容這些修改，（舊）程式碼仍將能夠編譯，即便升級了 Rust 編譯器的版本。

所有 Rust 編譯器都支援任何之前存在的編譯器版本，並可以連結任何支援版本的 crate。編譯器修改隻影響最初的解析程式碼的過程。因此，如果你使用 Rust 2015 而某個依賴使用 Rust 2018，你的專案仍舊能夠編譯並使用該依賴。反之，若專案使用 Rust 2018 而依賴使用 Rust 2015 亦可工作。

有一點需要明確：大部分功能在所有版本中都能使用。開發者使用任何 Rust 版本將能繼續接收最新穩定版的改進。然而在一些情況，主要是增加了新關鍵字的時候，則可能出現了只能用於新版本的功能。只需切換版本即可利用新版本的功能。

更多細節請參見 [_Edition Guide_][edition-guide]。這是一本完整的指南，列舉了不同 edition 之間的差異，並說明了如何透過 `cargo fix` 自動將程式碼升級到新的 edition。
