# 錯誤處理

[ch09-00-error-handling.md](https://github.com/rust-lang/book/blob/13e27c4a35705c4bd473bd90a3d3a8f87ef9ae58/src/ch09-00-error-handling.md)

錯誤是軟體中的常態，因此 Rust 提供了許多特性來處理某些事情出錯的情況。在很多場景下，Rust 會要求你先承認錯誤發生的可能性，並在程式碼能夠透過編譯之前採取一些行動。這項要求會讓程式更健壯，因為它確保你會在把程式碼部署到生產環境之前就發現錯誤，並妥善處理它們。

Rust 將錯誤分成兩大類：**可恢復的**（*recoverable*）和**不可恢復的**（*unrecoverable*）錯誤。對於可恢復錯誤，例如“檔案未找到”這樣的錯誤，我們多半隻想把問題報告給使用者，然後重試這次操作。不可恢復錯誤則總是 bug 的徵兆，比如試圖訪問陣列末尾之外的位置，因此我們希望立刻停止程式。

大多數語言並不區分這兩類錯誤，而是使用諸如異常（exception）之類的機制以相同方式處理它們。Rust 沒有異常。相反，它使用 `Result<T, E>` 型別來處理可恢復錯誤，使用 `panic!` 宏在程式遇到不可恢復錯誤時停止執行。本章會先介紹如何呼叫 `panic!`，然後再講如何返回 `Result<T, E>` 值。此外，我們還會探討：在決定是嘗試從錯誤中恢復，還是直接停止執行時，需要考慮哪些因素。
